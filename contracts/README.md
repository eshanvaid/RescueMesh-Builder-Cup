# Frozen event contract v1

An envelope has exactly `event_b64` and `signature_b64`. Decode event_b64 using strict standard base64; verify ECDSA P-256/SHA-256 with the registered origin's X.509/SPKI public key, and ASN.1 DER signature. Sign and retain the ORIGINAL UTF-8 bytes. JSON canonicalization is not required or used. Event ID is UUID; origin_device_id is the first 32 lowercase hex characters of SHA-256(SPKI). Trust manifest binds mission and device IDs to keys. Sequence is positive and durable, not a completeness watermark. Reject reuse of a sequence or event ID with differing bytes. Timestamps describe reports, never settle conflicts.

Mission `synthetic-flood-01`; locations `river-school`, `east-bridge`, `hill-clinic`. Seven event types: observation, question, answer, assessment, proposal, approval, delivery-receipt. Payload always includes incident_id and location_id. Observations/answers include text and optional claims (subject/predicate/value strings). Answers reference questions. Assessment/proposal payloads contain validated `assessment` (contracts/assessment.schema.json), provider, model, evidence_revision. Device-created approval events are forbidden at cloud ingestion; central approval creates a signed versioned approval event and an authenticated audit record in the same resource transaction. The central origin key persists privately on the backend, and public records expose only its public key. Central approvals remain cloud-only; phone-to-cloud ingestion rejects device approval events.

Limits: original event ≤12 KiB; refs ≤32; text ≤2000 chars; claims ≤8; peer packet ≤30 KiB; batch ≤2 events; inventory page ≤64 IDs; total mission ≤250 events/750 KiB cloud state. Demo bounds are enforced with visible capacity errors. Attachments and photos deferred until hardware gate passes; no media rides essential event packets.

Peer JSON messages: `{kind:"inventory",ids:[...],offset:0,next:64|null}`, `{kind:"inventory_request",offset:64}`, `{kind:"request",ids:[...]}`, `{kind:"events",events:[envelope,...]}`, `{kind:"ack",ids:[...]}`. Always enumerate IDs; request missing IDs; acknowledge only after Room transaction. Duplicate bytes are idempotent. Retry inventories in foreground with exponential backoff capped at 30 seconds, reconnect enumerates from zero. Peers prove registered key possession by signing a fresh receiver nonce (kind challenge/proof), bound to both device IDs and mission. A `ready` handshake ensures both proofs have completed before inventory exchange, including reordered proof/ready delivery. Nearby authentication digits must ALSO be confirmed by both humans. New source evidence creates a durable signed delivery-receipt event; those receipts do not generate further receipts.

Nearby encrypts the connection. Signed events authenticate origins and detect tampering. Untrusted relays can read them: end-to-end confidentiality is not implemented.
